# PhishDet

Веб-приложение для определения фишинговых ссылок с использованием машинного обучения и оплатой подписок через ЮKassa.

## Как запустить на новом компьютере

1. Клонируйте репозиторий:
   ```bash
   git clone <ссылка_на_твой_репозиторий>
   cd WebPhish
   
# Windows

python -m venv .venv
.venv\Scripts\activate

# macOS / Linux
python3 -m venv .venv
source .venv/bin/activate

# Установка зависимостей сервера (в api/requirements.txt лежит лишнее — numpy, torch и т.п., они для запуска сайта не нужны)
pip install -r requirements-server.txt

# (Необязательно) Скопируйте .env.example в .env и укажите свои ключи ЮKassa:
#   cp .env.example .env        # macOS / Linux
#   copy .env.example .env      # Windows
# Без .env всё работает на локальной SQLite-базе (файл phishdet.db создастся сам)
# и тестовых ключах оплаты.

# Запустите сервер
uvicorn api.main:app --reload --port 8000

# Откройте в браузере: http://127.0.0.1:8000

## Где что лежит

- `api/` - бэкенд на FastAPI.
- `static/` - сайт (HTML, CSS, JS). Сервер раздаёт наружу **только эту папку**:
  `.env`, `admin.env`, база и исходники снаружи недоступны. Новые страницы кладите сюда.

## Почта: подтверждение и сброс пароля

После регистрации пользователь получает письмо со ссылкой на подтверждение почты.
Пока почта не подтверждена, проверять ссылки и оплачивать подписку нельзя.
Повторно отправить письмо можно в личном кабинете. Там же меняется пароль, а на странице
входа есть «Забыли пароль?».

Без настроек SMTP письма никуда не уходят, а **печатаются в консоль сервера** вместе
со ссылкой. Для локальной разработки этого достаточно. Для настоящей отправки укажите
`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` в `.env`
(см. `.env.example`), а `PUBLIC_BASE_URL` - адрес сайта, из него собираются ссылки в письмах.

Требования к паролю: от 8 символов, хотя бы одна буква и одна цифра, не повторяет почту
и не входит в список самых частых паролей.

## Ограничение частоты запросов

Вход, регистрация, сброс пароля, отзывы, проверки и создание платежа ограничены
по частоте (`api/rate_limit.py`). При превышении сервер отвечает `429` с заголовком
`Retry-After`. Счётчики живут в памяти процесса: при запуске в несколько воркеров
или на нескольких серверах их нужно перенести в Redis. За прокси (nginx) включите
`TRUST_PROXY=1`, чтобы учитывался реальный IP из `X-Forwarded-For`.

## Оплата

Оплата идёт через ЮKassa (`api/payment.py`). Ключи - в `.env`: `YOOKASSA_SHOP_ID`
и `YOOKASSA_SECRET_KEY` (личный кабинет ЮKassa → Интеграция → Ключи API). Тестовый
магазин создаётся сразу после регистрации в ЮKassa, договор для него не нужен.
Тестовые карты: https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing

Как это работает:

1. Платёж создаётся на сервере и сохраняется в таблице `payments`.
2. Покупатель платит на странице ЮKassa и возвращается на `payment-result.html`.
3. Подписку включает уведомление ЮKassa на `/api/payment/webhook`. Уведомления
   не подписаны, поэтому сервер по id из уведомления сам запрашивает платёж у ЮKassa
   и сверяет статус, сумму и номер заказа. Подписка по одному платежу выдаётся
   ровно один раз, даже если уведомление придёт повторно.
4. Если уведомление ещё не пришло, страница возврата сама спрашивает статус
   у ЮKassa - поэтому оплата работает и локально, без публичного адреса.

Для боевого запуска в личном кабинете ЮKassa (Интеграция → HTTP-уведомления)
укажите адрес `https://<ваш-домен>/api/payment/webhook` и включите события
`payment.succeeded` и `payment.canceled`.

Чеки по 54-ФЗ: если подключены «Чеки от ЮKassa», оставьте `YOOKASSA_SEND_RECEIPT=1`
и проверьте у бухгалтера ставку НДС (`YOOKASSA_VAT_CODE`). Чек уходит на почту аккаунта.

## Модерация отзывов

Отзыв с формы на сайте не попадает в журнал сразу - он уходит в очередь модерации.
Администратор проверяет его на странице `/admin.html` и одобряет, снимает или удаляет.

Логин и пароль администратора задаются в файле **`admin.env`** в корне проекта.
Этот файл в git не попадает. Создайте его по образцу:

```
cp admin.env.example admin.env        # macOS / Linux
copy admin.env.example admin.env      # Windows
```

и впишите свою почту и надёжный пароль. Пароля по умолчанию нет: без файла
администратор не создаётся. После правки файла перезапустите сервер - учётная запись
администратора обновится сама, а старые входы администратора закончатся. Администратор
ровно один - тот, что указан в файле. Переменные окружения `ADMIN_EMAIL` и
`ADMIN_PASSWORD` работают как запасной вариант, если файла нет.

Ручки модерации (нужен токен администратора)

- `GET /api/admin/reviews?status_filter=pending|published|all`
- `PATCH /api/admin/reviews/{id}` с телом `{"is_published": true|false}`
- `DELETE /api/admin/reviews/{id}`

В журнале на лендинге видно не больше трёх отзывов за раз. Кнопка «далее» справа
листает остальные.
